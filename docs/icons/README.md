# 图标素材库

**先读这一段，再动手。** 这个仓库的图标出过两次事故，两次都是因为**按文件名猜图标归属**：

1. 用户导出的文件名叫 `pdf图标.png`，内容其实是**软件主图标**，被误装到了 PDF 文档图标位置；
2. 留下的 `最终-PDF文档图标-裁剪版.ico` 名字里写着"最终"，实际是**被推翻的废稿**（大红 P 被裁掉一半）。

> **铁律：判断图标归属只看内容 + 上下文，绝不信文件名。**

## 一、当前实际使用的图标

只有 `overrides/icons/` 下这 4 个文件参与构建，它们被 workflow 直接覆盖进上游源码：

| 上游文件 | 我们的覆盖文件 | 显示位置 |
|---|---|---|
| `assets/app-icon/pdfcraft.ico` | `overrides/icons/pdfcraft.ico` | exe 资源 1 → 任务栏 / 开始菜单 / 快捷方式 |
| `assets/app-icon/pdfcraft-document.ico` | `overrides/icons/pdfcraft-document.ico` | exe 资源 2 → PDF 文件关联图标 |
| `assets/app-icon/pdfcraft-document.svg` | `overrides/icons/pdfcraft-document.svg` | Linux / macOS 的 PDF 文件图标 |
| `assets/app-icon/hicolor/256x256/apps/ai.storyteller.pdfcraft.png` | `overrides/icons/hicolor-256-app.png` | **窗口左上角**（`include_bytes!` 编译期内嵌） |

> 第三处的窗口图标是 `include_bytes!` 编译进去的 PNG，**换 ico 对它无效**，必须换那张 PNG。
> 换图标时四处都要动，最容易漏的是最后那个 PNG。

**外观约定**（用户定稿）：

- **软件主图标 + 窗口图标** = 大红 P（白色折角文件 + 大红字母 P + 米色纸面 + 红描边）
- **PDF 文档图标** = 方案 A（白纸 + 红色「PDF」徽章 + 白字），与上游原图标同结构，只把绿色换成红色

上游原来的狮子 logo 是 ArtCraft 的商标，所以整套换成用户自制图标，既避开商标也解决中文化观感问题。

## 三、改图标的完整流程

1. 用户在浏览器里打开上面的 HTML 工具，调好 → 「导出 PNG」→ 把 PNG 发过来
2. **先看清楚这张图是给哪个位置用的**（软件主图标？窗口图标？PDF 文档图标？）——别信文件名
3. 处理成目标格式（Pillow 环境见 `docs/维护指南.md` §9）：
   - **ico**：裁剪透明边 → 正方形画布居中（**上下贴边**）→
     `img.save('x.ico', format='ICO', sizes=[(16,16),(20,20),(24,24),(32,32),(40,40),(48,48),(64,64),(128,128),(256,256)])`
     > **必须用 `sizes=` 让 Pillow 自动缩放，不能用 `append_images`** —— ICO 格式下
     > `append_images` 无效，只会存下第一个尺寸。
   - **窗口图标 PNG**：同样裁剪贴边后 `resize((256,256))` 存 PNG
   - **SVG**：必须用本机 Chrome headless 渲染，**Pillow 手画复杂路径不可靠**
4. 覆盖 `overrides/icons/` 里对应文件（**四个位置都要检查，最容易漏窗口 PNG**）
5. 触发构建，按 `docs/维护指南.md` 铁律 1 回读日志，确认三行图标替换都执行
6. 把新的**源图**也存一份到本目录，标注它对应哪个位置
