这里只存**真正还会用到的东西**：唯一真源、源图、以及用户以后调图标要用的网页工具。
废弃的、错误的、被取代的稿子**一律不留** —— 但踩过的坑记在下面，免得再踩第二次。

> 目录里只剩 7 个文件，其中 4 个是工具网页。改图标只认下面「当前实际使用」那一节。

## 三、踩过的坑（务必避免重犯）

这个仓库的图标出过两次事故，根源都是**没看内容就动手**。错误稿子已全部删除，只留下教训。

### 1. 大红 P 会溢出画布 —— 导出后必须目视检查

早期的大红 P 稿里，字母 P 比文件本体大，**左侧和顶部被画布裁掉**。基于它的 ico 用在
PDF 文件图标位置上，用户一眼看出不对 —— 那次「图标装错位置」的事故就是这么来的。

**规矩：**

- 用 `方案B-拖动P调整.html` 这类工具导出 PNG 后，**先自己看一眼**，确认 P 没被裁
- 导出的原图应当是**正方形、内容完整不溢出**；不完整就调好再导
- 拿到任何新图标，**先确认它是哪个位置的图标**，再动手

### 2. 绝对不要按文件名猜图标归属

用户的导出文件名曾经叫 `pdf图标.png`，但内容其实是**软件主图标**（大红 P），
被误当成了 PDF 文档图标装上去。

**规矩：判断图标归属只看图片内容 + 对话上下文，绝不信文件名。**

### 3. 不要给文件起误导性的名字

曾经留下过一个叫 `最终-…-裁剪版.ico` 的文件，名字里写着「最终」，
实际是上面第 1 条那个有缺陷的稿子。后来它成了唯一的「最终版本」候选，差点又被用上。

**规矩：文件名只描述内容，不描述评价。「最终」「最新」这类词会过期并骗人。**

### 4. 四个图标位置，一个都不能漏

软件一共有**三处**图标来源，但需要维护的是**四个文件**（软件主图标在 exe 里有资源 1 和窗口 PNG 两处）。
漏掉窗口 PNG 的后果是：任务栏图标换了、窗口左上角还是旧的。

## 四、改图标的完整流程

1. 用户在浏览器里打开上面的工具网页，调好 → 「导出 PNG」→ **先目视检查 P 没被裁** → 发过来
2. **确认这张图是给哪个位置用的**（软件主图标 / 窗口图标 / PDF 文档图标）—— 别信文件名
3. 处理成目标格式（Pillow 环境见 `docs/维护指南.md` §9）：
   - **ico**：裁剪透明边 → 正方形画布居中（**上下贴边**）→
     `img.save('x.ico', format='ICO', sizes=[(16,16),(20,20),(24,24),(32,32),(40,40),(48,48),(64,64),(128,128),(256,256)])`
     > **必须用 `sizes=` 让 Pillow 自动缩放，不能用 `append_images`** —— ICO 格式下
     > `append_images` 无效，只会存下第一个尺寸。
   - **窗口图标 PNG**：同样裁剪贴边后 `resize((256,256))` 存 PNG
   - **SVG**：必须用本机 Chrome headless 渲染，**Pillow 手画复杂路径不可靠**
4. 覆盖 `overrides/icons/` 里对应文件（**四个位置都要检查，最容易漏窗口 PNG**）
5. 触发构建，按 `docs/维护指南.md` 铁律 1 回读日志，确认三行图标替换都执行
6. 把新的**源图**也存一份到本目录，并在这份 README 里写清它对应哪个位置
7. 旧稿如果没有复用价值，**直接删掉**，不要留在仓库里占位、更不要起误导性的名字
